# Уроки по работе с AI-ассистентом

## Анализ ошибок при реализации функционала автоматического биддера

### 1. Ошибки с импортами и структурой проекта

#### Неправильное расположение моделей
- **Ошибка**: Попытка импорта `AdvSetting` из `app.modules.wb_adv_updater.models`
- **Правильно**: `app.modules.common_slaves.wildberries.models`
- **Причина**: Незнание структуры модулей проекта и расположения моделей для работы с рекламными кампаниями

#### Неправильное расположение UI-компонентов
- **Ошибка**: Попытка импорта `CPMSettingMenu` из `app.modules.wb_adv_updater.callback_data`
- **Правильно**: `app.client_bot.user_interface.views.callbacks`
- **Причина**: Непонимание разделения UI-компонентов в отдельном модуле `client_bot`

### 2. Ошибки с объектами и их жизненным циклом

#### Неправильная инициализация CPMSetting
- **Ошибка**: Создание с тремя параметрами: `CPMSetting(callback.bot, callback.message.chat.id, adv_setting)`
- **Правильно**: `CPMSetting(callback.bot, callback.message.chat.id)`
- **Причина**: Незнание двухэтапного процесса инициализации объекта (сначала базовые параметры, затем получение adv_setting через __call__)

### 3. Ошибки в тестировании

#### Неправильная настройка моков
- **Ошибка**: Использование `MagicMock` с `__call__` для асинхронного объекта
- **Правильно**: Использование `AsyncMock` для объектов, вызываемых через `await`
- **Причина**: Непонимание асинхронной природы компонентов

#### Неполная проверка вызовов
- **Ошибка**: Проверка только создания объекта `CPMSetting`
- **Правильно**: Проверка и создания объекта, и вызова его метода `__call__` с правильными параметрами
- **Причина**: Неучет двухэтапного процесса инициализации и использования `CPMSetting`

### 4. Ошибки с устаревшим кодом

#### Работа с устаревшими тестами
- **Ошибка**: Попытка исправить импорт `CalculatedKeyword` в устаревшем тесте
- **Правильно**: Удаление устаревшего теста `test_advertising_campaign_statistic_message.py`
- **Причина**: Непонимание, что тест был устаревшим и больше не актуален

### 5. Архитектурные недопонимания

#### Незнание архитектуры проекта
- Непонимание разделения на модули `common_slaves`, `client_bot` и их ролей
- Незнание правильного расположения UI-компонентов (сообщения, клавиатуры)
- Непонимание жизненного цикла объектов и их инициализации

### 6. Опыт реализации bidder_auto_mode

#### Работа с сессиями SQLAlchemy
- **Проблема**: Первоначально использовали `data_manager` для работы с БД
- **Решение**: Перешли на прямое использование сессий через `get_async_session_maker`
- **Причина**: Более гибкий контроль над транзакциями и лучшая тестируемость

#### Тестирование с моками сессий
- **Проблема**: Сложности с мокированием асинхронных сессий SQLAlchemy
- **Решение**: 
  - Использование `AsyncMock` для сессии
  - Правильная настройка возвращаемых значений для `execute` и `scalar`
  - Проверка вызова `commit` в тестах
- **Причина**: Асинхронная природа сессий SQLAlchemy требует особого подхода к мокированию

#### Миграции с Alembic
- **Проблема**: Необходимость добавления нового поля `bidder_for_auto` в модель `AdvSetting`
- **Решение**: 
  - Создание миграции с правильным именем и описанием
  - Использование `op.add_column` с правильным типом данных
  - Добавление значения по умолчанию для существующих записей
- **Причина**: Важность правильного управления схемой базы данных

#### Интеграция с существующим кодом
- **Проблема**: Необходимость встраивания нового функционала в существующую систему
- **Решение**:
  - Изучение существующих обработчиков и их структуры
  - Следование паттернам именования и организации кода
  - Переиспользование существующих компонентов UI
- **Причина**: Важность поддержания единообразия кодовой базы

## Выводы и рекомендации

1. **Изучение структуры проекта**
   - Перед началом работы необходимо изучить структуру модулей
   - Понять разделение на UI, бизнес-логику и модели
   - Изучить архитектурные решения проекта

2. **Работа с асинхронным кодом**
   - Правильно использовать `AsyncMock` для асинхронных объектов
   - Проверять все этапы асинхронных операций
   - Учитывать жизненный цикл асинхронных объектов

3. **Тестирование**
   - Проверять все этапы инициализации и использования объектов
   - Правильно настраивать моки для асинхронных компонентов
   - Своевременно удалять устаревшие тесты

4. **Документация**
   - Документировать архитектурные решения
   - Описывать жизненный цикл объектов
   - Поддерживать актуальность тестов
