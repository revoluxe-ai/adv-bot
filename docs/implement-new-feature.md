# Правила разработки новых функций

> **Важно**: Подробный план развития проекта и текущие цели находятся в директории `memory-bank/`:
> - Общее описание проекта: `memory-bank/00-project-overview.md`
> - План развития: `memory-bank/01-development-roadmap.md`

## Общие принципы
- Перед началом разработки ознакомиться с общими планами развития проекта
- Следовать архитектурным решениям, принятым в проекте
- Придерживаться единого стиля кодирования

## Архитектурные требования
1. **Базовые абстракции:**
   - Все новые объекты должны наследоваться от соответствующих базовых абстрактных классов
   - Моки для тестирования должны использовать базовые классы моков
   - Строго соблюдать единую сигнатуру методов, определенную в базовых классах
   - При необходимости расширения базового функционала - сначала обсудить изменения базовых классов

2. **Совместимость:**
   - Проверять совместимость с существующими компонентами системы
   - Учитывать влияние новых функций на существующий функционал
   - Следить за обратной совместимостью при изменении интерфейсов

## Процесс разработки
1. **Планирование:**
   - Изучить общие планы развития проекта
   - Определить, как новая функция вписывается в общую архитектуру
   - Выявить зависимости с другими компонентами

2. **Реализация:**
   - Использовать существующие абстракции и базовые классы
   - Следовать принципам SOLID
   - Документировать код и API

3. **Тестирование:**
   - Создавать моки на основе базовых классов моков
   - Обеспечить покрытие тестами
   - Проверять граничные случаи
