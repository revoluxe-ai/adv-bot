# Тестирование проекта

## Запуск тестов

Для запуска тестов используйте команду:

```bash
pytest -x
```

Эта команда:
- Запускает все тесты в проекте
- Останавливается при первой же ошибке (`-x`)
- Показывает подробный отчет о результатах

### Дополнительные опции запуска

1. Запуск с подробным выводом:
```bash
pytest -x -v
```

2. Запуск конкретного теста:
```bash
pytest tests/test_file.py::test_function_name -x
```

3. Запуск с выводом print-сообщений:
```bash
pytest -x -s
```

## Отладка тестов

### Использование breakpoint

В коде теста можно использовать:
```python
breakpoint()  # Python 3.7+
```
или
```python
import pdb; pdb.set_trace()  # Для более старых версий
```

### Асинхронные тесты

Для асинхронных тестов используйте декоратор:
```python
@pytest.mark.asyncio
async def test_async_function():
    # Ваш тест
```

## Структура тестов

1. Каждый тест должен проверять одну конкретную функциональность
2. Используйте фикстуры для переиспользования кода
3. Мокайте внешние зависимости
4. Проверяйте граничные случаи

## Правила написания тестов

1. Называйте тесты понятно и описательно
2. Следуйте паттерну AAA (Arrange-Act-Assert)
3. Не забывайте про очистку после тестов
4. Документируйте сложные тесты

## Частые проблемы и их решение

1. **Ошибка с аргументами в моках**:
   - Проверьте сигнатуру реальной функции
   - Убедитесь, что мок принимает все нужные аргументы
   - Используйте `side_effect` для разных сценариев

2. **Проблемы с асинхронными тестами**:
   - Проверьте все ли корутины правильно ожидаются
   - Используйте правильные фикстуры
   - Проверьте контекстные менеджеры

3. **Проблемы с базой данных**:
   - Используйте тестовую базу данных
   - Очищайте данные после тестов
   - Мокайте запросы к БД

## Советы по написанию тестов

1. Пишите тесты до написания кода (TDD)
2. Поддерживайте тесты в актуальном состоянии
3. Регулярно запускайте все тесты
4. Используйте CI/CD для автоматического запуска тестов
