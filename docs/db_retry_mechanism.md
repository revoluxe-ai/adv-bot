# Механизм повторных попыток соединения с базой данных

## Проблема

Пользователи периодически получают ошибку `ConnectionError: unexpected connection_lost() call`, что указывает на неожиданную потерю соединения с базой данных PostgreSQL. Это может происходить по разным причинам:

1. Нестабильное сетевое соединение
2. Достижение лимита соединений к базе данных
3. Проблемы с SSL/TLS соединением
4. Тайм-ауты операций с базой данных
5. Перегрузка базы данных

## Решение

Разработан механизм автоматического повторения запросов при потере соединения с базой данных, который:

1. **Не вносит изменений в основной код проекта**
2. **Создает обертки для существующих функций**
3. **Автоматически повторяет операции при возникновении ошибок соединения**
4. **Использует экспоненциальную задержку между попытками**
5. **Логирует все попытки и ошибки**

## Пример использования

### 1. Декоратор для функций с доступом к базе данных

```python
from tests.test_db_retry import with_db_retry

# Применение декоратора к функции обработчика
@with_db_retry(max_retries=3, retry_delay=0.5)
async def get_user_data(user_id: int) -> User:
    async with get_async_session_maker() as session:
        stmt = select(User).where(User.id == user_id)
        result = await session.execute(stmt)
        return result.scalar_one_or_none()
```

### 2. Класс-обертка для обработчиков

```python
from tests.test_db_retry import with_db_retry
from app.client_bot.user_interface.handlers.start_registration_func import start_registration

# Класс с обертками для обработчиков
class UserHandlersWithRetry:
    @staticmethod
    @with_db_retry(max_retries=3, retry_delay=0.5)
    async def start_registration(message, bot, state):
        return await start_registration(message, bot, state)
    
    # Другие обработчики с ретраями
```

### 3. Прямое использование функции обертки

```python
from tests.test_db_retry import retry_async_db_operation

async def handle_user_request(user_id: int):
    try:
        # Применение функции повторных попыток
        user_data = await retry_async_db_operation(
            get_user_data,
            user_id,
            max_retries=3,
            retry_delay=0.5
        )
        return user_data
    except Exception as e:
        logger.error(f"Cannot get user data after multiple attempts: {e}")
        raise
```

## Параметры настройки

- **max_retries** - максимальное количество попыток (включая первую)
- **retry_delay** - начальная задержка между попытками в секундах
- **exponential_backoff** - использовать ли экспоненциальное увеличение задержки между попытками
- **retry_exceptions** - кортеж исключений, при которых нужно повторять попытки

## Рекомендуемые настройки для различных операций

| Тип операции | max_retries | retry_delay | exponential_backoff |
|--------------|-------------|-------------|--------------------|
| Регистрация  | 3           | 0.5         | True               |
| Чтение данных| 3           | 0.3         | True               |
| Запись данных| 5           | 0.5         | True               |
| Важные транзакции | 5      | 1.0         | True               |

## Рекомендации по внедрению

1. **Приоритизация функций:**
   - Начните с функций, которые чаще всего вызывают ошибки (например, start_registration)
   - Добавьте повторные попытки для функций с высоким уровнем использования
   - Обновите обработчики критических операций (платежи, регистрация)

2. **Развертывание:**
   - Протестируйте механизм повторных попыток в тестовой среде
   - Добавляйте повторные попытки постепенно, начиная с 1-2 обработчиков
   - Мониторьте логи на наличие ошибок и повторных попыток

3. **Мониторинг:**
   - Настройте логирование всех повторных попыток
   - Создайте дашборд для отслеживания частоты повторных попыток
   - Установите оповещения при частых повторных попытках (возможная проблема с БД)

4. **Оптимизация базы данных:**
   - Параллельно с внедрением механизма повторных попыток оптимизируйте:
     - Настройки пула соединений
     - Время тайм-аутов соединений
     - Масштабируйте базу данных при необходимости
