# План изменений формата отображения статистики

## Общее описание
План описывает изменения в формате отображения статистики рекламных кампаний. Основная цель - сделать отображение более структурированным и читаемым, сохранив при этом всю существующую функциональность.

## Текущая реализация
- Статистика отображается в методе `text` класса `AdvSettingMenu`
- Текущий формат: `дата: себестоимость (заказы) (затраты) р.`
- Сортировка по дате
- Ограничение на последние 5 дней

## План изменений

### 1. Изменение формата отображения
```python
# Текущий формат:
stat_text = 'Себестоимость заказа за последние дни (заказы) (затраты):\n'
stat_text += f'{date}: {round(cost_per_order, 0)} ({orders}) ({spend}) р.\n'

# Новый формат:
stat_text = 'Статистика по дням:\n'
stat_text += 'Дата | Заказы | Себестоимость заказа\n'
stat_text += '--------------------------------\n'
stat_text += f'{date} | {orders} | {round(cost_per_order, 0)} р.\n'
```

### 2. Детали реализации
- Сохранить сортировку по дате
- Сохранить ограничение на последние 5 дней
- Добавить разделители "|" для лучшей читаемости
- Округлять себестоимость заказа до целых рублей
- Добавить заголовок таблицы
- Добавить разделительную линию под заголовком

### 3. Сохранение существующей функциональности
- Оставить функцию `reverse_date` для форматирования даты
- Сохранить логику расчета `cost_per_order`
- Сохранить обработку случая, когда `orders = 0`

### 4. Проверка и тестирование
- Проверить корректность отображения всех данных
- Убедиться, что форматирование даты работает правильно
- Проверить корректность расчетов себестоимости
- Проверить отображение при отсутствии данных

### 5. Дополнительные улучшения (опционально)
- Добавить выравнивание столбцов для лучшей читаемости
- Добавить цветовое выделение для важных показателей
- Добавить суммарные показатели в конце таблицы

## Пример нового формата
```
Статистика по дням:
Дата | Заказы | Себестоимость заказа
--------------------------------
12-04-2024 | 5 | 150 р.
11-04-2024 | 3 | 200 р.
10-04-2024 | 4 | 175 р.
```

## Примечания
- Все изменения должны быть обратно совместимыми
- Необходимо сохранить существующую логику обработки данных
- Изменения касаются только формата отображения, не затрагивая бизнес-логику
