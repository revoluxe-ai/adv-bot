1. **Проблема с автогенерацией миграций (28.03.2025):**
   - При автогенерации миграции для таблиц WBBalancePayment и WBBonusPayment Alembic добавил множество лишних изменений, включая удаление таблиц, индексов и столбцов, которые используются в системе.
   - Миграция была вручную отредактирована, чтобы оставить только добавление новых таблиц.

   - Возможно, потребуется настроить сравнение метаданных в env.py Alembic.

2. **Средний приоритет:**
   - Создать отдельную ветку для работы с миграциями и проверки корректности.
   - Сделать резервное копирование базы данных перед применением миграций.
   - Проверить, соответствуют ли текущие модели схеме базы данных.

## Заметки

- В будущем желательно создавать миграции вручную или тщательно проверять автоматически сгенерированные.
- Убедиться, что тестовая среда имеет схему базы данных, соответствующую продакшену, чтобы избежать ложных миграций.

- Свойство `calculated_bonus` - суммирует значение поля `bonus` и записи из таблицы `wbbonuspayment`

## Запланированные миграции

### Удаление дублирования данных в балансе и бонусах
После полного перехода на новую систему учета через гибридные свойства можно будет рассмотреть 
возможность миграции, удаляющей дублирование данных:
- Перенос значений из полей `balance` и `bonus` в соответствующие таблицы транзакций
- Обнуление полей `balance` и `bonus`

Это позволит иметь единый источник правды для данных о балансе и бонусах, и избежать потенциальных ошибок
из-за рассинхронизации прямых полей и записей транзакций.
