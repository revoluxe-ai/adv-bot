
## Предложения по улучшению механизма прогнозирования

## Проблема

В файле `app/modules/common_advs_stat/data_manager.py` (строки 119-124) при отсутствии заказов или корзин за анализируемый период используются фиксированные значения (1 для заказов, 0.01 для корзин) для предотвращения деления на ноль. Это приводит к:
- Слишком оптимистичным прогнозам продаж.
- Завышенной себестоимости заказа.
- Отсутствию адекватного механизма обработки случаев с недостаточными данными.

## Предлагаемые решения

### 1. Адаптивное расширение окна анализа

**Идея:** Вместо фиксированного периода (например, 7 дней) динамически расширять окно анализа до тех пор, пока не будет набрано минимальное количество наблюдений (заказов/корзин) или не будет достигнут максимальный период.

**Детали реализации:**
- Определить набор окон (например, 7, 14, 30, 60, 90 дней).
- Для каждого окна выполнять один агрегирующий запрос к ClickHouse.
- Использовать `min_count` для определения минимального количества наблюдений для "валидного" окна.
- Если даже после максимального окна данных недостаточно, вернуть 0 или специальное значение, указывающее на их отсутствие.

**Пример псевдокода:**

```python
async def _get_metric_with_adaptive_window(
        self,
        adv: AdvSetting,
        metric: Literal["orders", "carts"],
        windows: tuple[int, ...] = (7, 14, 30, 60, 90),
        min_count: int = 5,
) -> tuple[float, int]:          # (value, used_days)
    for days in windows:
        value = await ch.get_common_metric_sum(adv, metric, days)
        if value >= min_count:
            return value, days
    return 0.0, windows[-1]       # совсем нет данных – явный 0
```

**Преимущества:**
- Более реалистичные прогнозы при отсутствии недавних продаж.
- Уменьшение смещения при сглаживании.
- Эффективное использование ClickHouse (один запрос на окно).

### 2. Байесовское сглаживание

**Идея:** Применить байесовский подход для оценки частоты событий (продаж/корзин), используя априорное знание о "типичной" частоте. Это позволяет получить более адекватные оценки при малом количестве данных.

**Детали реализации:**
- Используется формула: \( \hat{p} = \dfrac{k + \alpha}{n + \alpha + \beta} \)
  - \( k \) – число продаж (или корзин) за период.
  - \( n \) – число дней в периоде.
  - \( \alpha \), \( \beta \) – параметры априорного распределения (например, для товара, который обычно продаётся раз в 30 дней, можно взять \( \alpha = 1, \beta = 30 \)).
- Даже при \( k = 0 \), прогноз не будет нулевым, но будет "притянут" к априорному знанию.

**Пример применения:**
Если \( k = 0 \) продаж за \( n = 7 \) дней, и априорные \( \alpha = 1, \beta = 30 \), тогда:
\( \hat{p}_{7} = (0 + 1) / (7 + 1 + 30) \approx 0.026 \) заказа в день.

**Преимущества:**
- Статистически более обоснованный подход.
- Гибкая настройка через априорные параметры.
- Избегание как деления на ноль, так и излишне оптимистичных/пессимистичных прогнозов.

### 3. Иерархический Fallback

**Идея:** Если для конкретного объявления недостаточно данных, использовать данные с более высоких уровней агрегации.

**Порядок Fallback:**
Объявление → Категория товара → Вся витрина

**Детали реализации:**
- Вычислять среднюю конверсию/частоту для каждой иерархии.
- Использовать эти значения как "априорные" (или как запасные) для объявлений с недостаточной собственной статистикой.

**Преимущества:**
- Дополнительная устойчивость прогнозов.
- Использование всего доступного контекста.

### Что с ClickHouse?

ClickHouse позволяет легко агрегировать данные за любой период с помощью `sum()` и `date >= today() - INTERVAL {days} DAY;`. Выполнение нескольких таких запросов для адаптивного окна будет быстрым и эффективным.

### Прозрачность для пользователя

Важно ясно коммуницировать пользователю, когда прогноз основан на:
- Прямых продажах за короткий период.
- Расширенном периоде анализа.
- Байесовском сглаживании.
- Данных с более высоких уровней агрегации.

Это можно сделать через UI или в отчетах, чтобы пользователь понимал, почему прогноз может отличаться от его интуитивных ожиданий. Например, показывать "Прогноз (сглажено)" или "Прогноз (расширенное окно: 30 дней)".
