# Тестирование изменений в парсере

В данном документе описаны тесты, созданные для проверки функциональности парсера Wildberries и его оптимизаций с использованием Redis.

## Что тестируем

Основная функциональность, которая тестируется:

1. **Взаимодействие с Redis** - проверка правильного отслеживания найденных и не найденных позиций в Redis.
2. **Оптимизация очереди страниц** - проверка, что парсер сначала проверяет страницы, где ранее были найдены позиции.
3. **Обработка ошибок** - проверка механизма обработки ошибок и повторных попыток.

## Описание тестов

### 1. Тест класса `ParsingQueueManager`

**Файл:** `test_parsing_queue_manager.py`

**Метод `add_found_not_found_page`**:
- Проверяет, что информация о найденных и не найденных позициях правильно сохраняется в Redis.
- Если nmid был найден на странице, метод вызывает `add_last_found_page_for_text_nmid` для Redis.
- Если nmid не был найден на странице, метод вызывает `add_last_not_found_page_for_text_nmid` для Redis.

**Метод `get_parsing_queue`**:
- Проверяет, что метод возвращает оптимизированную очередь страниц для парсинга.
- Сначала в очереди должны быть страницы, где ранее находились позиции.
- Затем идут страницы, которые еще не проверялись.
- В конце идут страницы, где ранее не было найдено позиций.

### 2. Тест класса `ParsingFoundRedisManager`

**Файл:** `test_parsing_found_redis_manager.py`

**Методы для хранения данных в Redis**:
- `add_last_found_page_for_text_nmid` - проверяет правильное сохранение информации о найденной странице в Redis.
- `add_last_not_found_page_for_text_nmid` - проверяет правильное сохранение информации о не найденной странице в Redis.

**Методы для получения данных из Redis**:
- `get_found_pages_for_text_nmid` - проверяет правильное получение списка страниц, где находилась позиция.
- `get_not_found_pages_for_text_nmid` - проверяет правильное получение списка страниц, где не находилась позиция.

### 3. Интеграционные тесты парсера

**Файл:** `test_parser_integration.py`

**Тест использования очереди парсинга**:
- Проверяет, что парсер использует `ParsingQueueManager` для определения порядка страниц.
- Проверяет вызов метода `get_parsing_queue` с правильными параметрами.

**Тест отслеживания найденных позиций**:
- Проверяет, что парсер вызывает `add_found_not_found_page` для каждой обработанной страницы.
- Проверяет правильность передачи параметров при вызове метода.

**Тест оптимизации с использованием данных из Redis**:
- Проверяет, что парсер останавливается после нахождения всех нужных позиций.
- Проверяет, что страницы запрашиваются в оптимизированном порядке, полученном от `ParsingQueueManager`.

**Тест обработки ошибок**:
- Проверяет механизм повторных попыток при возникновении ошибки `DataError`.
- Проверяет, что при повторе запроса результат корректно обрабатывается.

## Как запускать тесты

Для запуска тестов используйте следующую команду:

```bash
python -m pytest tests/test_parser_integration.py -v
python -m pytest tests/test_parsing_queue_manager.py -v
python -m pytest tests/test_parsing_found_redis_manager.py -v
```

## Подготовка окружения для тестирования

1. Активируйте виртуальное окружение проекта:
   ```bash
   source venv/bin/activate  # Linux/Mac
   venv\Scripts\activate    # Windows
   ```

2. Установите зависимости для тестирования:
   ```bash
   pip install pytest pytest-asyncio pytest-mock
   ```

3. Убедитесь, что в директории `app/modules/keywords_query/` присутствует файл `requests.csv`. Если его нет, создайте пустой файл или используйте мок-объекты в тестах.

## Результаты тестирования

При успешном прохождении всех тестов вы должны увидеть сообщение вида:

```
===== X passed in X.XX seconds =====
```

Если тесты завершаются с ошибками, изучите сообщения об ошибках для определения причины.

## Потенциальные проблемы и их решение

1. **Ошибка доступа к Redis**: убедитесь, что у вас настроен Redis для тестирования или используются моки.

2. **Отсутствует файл requests.csv**: создайте пустой файл или используйте моки для модуля keywords_query.

3. **Зависимости импорта**: если возникают проблемы с циклическими импортами, импортируйте модули внутри тестовых функций, а не на уровне модуля.
