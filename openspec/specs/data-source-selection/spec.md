## Purpose

Правила выбора источника dataset магазина: отделение сбора от управления РК,
чтение AI Package из накопленных PostgreSQL/ClickHouse, карточка источника и
открытый вопрос товарной ленты заказов/продаж. Synced from change
`ai-package-data-source-strategy` (planning-only).

## Requirements

### Requirement: Сбор отделён от управления кампаниями

Подключённый магазин MUST собирать данные по всем своим артикулам и всем доступным рекламным кампаниям независимо от того, подключены ли кампании к управлению WB Sky. Сбор данных и управление кампаниями MUST оставаться разными контурами. Сбор MUST NOT менять `bot_active` и MUST NOT выдавать новых прав на запись в WB. Сбор MUST NOT назначать mode defaults и MUST NOT вызывать paid/free transition, который переводит кампанию в управление ботом. Процедура обнаружения кампаний, которых ещё нет в инвентаре, этим требованием не задаётся.

#### Scenario: Сбор охватывает все артикулы и доступные кампании

- **GIVEN** магазин подключён к контуру сбора
- **WHEN** определяется состав сбора
- **THEN** сбор MUST включать все артикулы магазина и все доступные рекламные кампании
- **AND** подключение кампании к управлению WB Sky MUST NOT быть условием включения в сбор

#### Scenario: Сбор не меняет bot_active и не даёт прав записи

- **GIVEN** контур сбора читает или накапливает dataset магазина
- **WHEN** сбор выполняется
- **THEN** `bot_active` MUST NOT измениться
- **AND** новых прав на запись в WB MUST NOT появиться
- **AND** mode defaults MUST NOT назначаться из сбора
- **AND** paid/free transition, переводящий кампанию в управление ботом, MUST NOT вызываться

#### Scenario: Обнаружение кампаний вне инвентаря не задаётся здесь

- **GIVEN** часть кампаний магазина ещё не входит в инвентарь
- **WHEN** стратегия описывает, кого обязан охватить сбор
- **THEN** процедура обнаружения таких кампаний MUST NOT задаваться этим требованием

### Requirement: Пакет читает уже накопленные данные

Основной источник AI Package MUST быть уже накопленные PostgreSQL и ClickHouse. Формирование ZIP MUST NOT запускать полный сбор магазина через WB API. Если накопления не хватает, пакет получает неполное `coverage` и `reason_codes`. Пустой успех и живой полный обход WB из ZIP эту нехватку не закрывают.

#### Scenario: ZIP читает PostgreSQL и ClickHouse

- **GIVEN** для магазина уже есть накопление в PostgreSQL и ClickHouse
- **WHEN** формируется ZIP пакета AI
- **THEN** основным источником MUST быть это накопление

#### Scenario: ZIP не запускает полный сбор WB

- **GIVEN** формируется ZIP пакета AI
- **WHEN** накопления не хватает или его нужно прочитать
- **THEN** полный сбор магазина через WB API из формирования ZIP MUST NOT запускаться
- **AND** нехватка MUST оставаться неполным `coverage` и `reason_codes`
- **AND** пустой успех MUST NOT закрывать эту нехватку

### Requirement: Карточка источника dataset

Для каждого dataset MUST быть зафиксированы основной источник, допустимый fallback, совместимость зерна и семантики метрики, сохранение provenance, приоритет, разбор противоречий, гранулярность, доступная история, правило обновления, права, зависимость от подписки и `reason_codes`. Этот change фиксирует состав карточки и общие запреты. Конкретный источник WB для dataset он не назначает, кроме уже принятого правила чтения пакета из накопленных PostgreSQL и ClickHouse. Будущий change накопления, который начнёт копить dataset, MUST заполнить карточку в этих границах.

#### Scenario: Карточка содержит обязательный состав

- **GIVEN** dataset входит в накопление магазина или в чтение пакета
- **WHEN** для него фиксируется источник
- **THEN** карточка MUST содержать основной источник, допустимый fallback, совместимость зерна и семантики метрики, provenance, приоритет, разбор противоречий, гранулярность, доступную историю, правило обновления, права, зависимость от подписки и `reason_codes`

#### Scenario: Этот change не назначает источник WB dataset

- **GIVEN** dataset ещё не имеет назначенного источника WB внутри этой стратегии
- **WHEN** применяется карточка источника
- **THEN** этот change MUST NOT назначать ему конкретный источник WB
- **AND** чтение пакета при этом MUST оставаться чтением уже накопленных PostgreSQL и ClickHouse

### Requirement: Fallback не подменяет метрику

Fallback MUST NOT молча подменять одну метрику другой. Fallback MUST NOT приниматься как факт dataset, если его зерно несовместимо с зерном dataset или его семантика несовместима с семантикой метрики dataset. Provenance MUST называть источник, из которого факт реально взят, и MUST NOT выдавать fallback за основной источник.

#### Scenario: Другая метрика не подменяет недостающую

- **GIVEN** у dataset зафиксированы основной источник метрики и допустимый fallback
- **WHEN** fallback возвращает иную метрику, чем метрика этого dataset
- **THEN** иная метрика MUST NOT записываться как недостающая метрика dataset
- **AND** подмена MUST NOT быть молчаливой

#### Scenario: Несовместимое зерно отклоняется

- **GIVEN** зерно fallback несовместимо с зафиксированным зерном dataset
- **WHEN** рассматривается запись факта dataset из этого fallback
- **THEN** fallback MUST NOT приниматься как факт dataset

#### Scenario: Несовместимая семантика отклоняется

- **GIVEN** семантика fallback несовместима с семантикой метрики dataset
- **WHEN** рассматривается подстановка fallback вместо этой метрики
- **THEN** fallback MUST NOT приниматься как эта метрика

#### Scenario: Provenance называет фактический источник

- **GIVEN** факт dataset записан из fallback, а не из основного источника
- **WHEN** читается provenance этого факта
- **THEN** provenance MUST называть fallback
- **AND** MUST NOT утверждать, что метрика пришла из основного источника

### Requirement: Противоречие источников разбирается явно

При противоречии допустимых источников разбор MUST применять зафиксированные для dataset приоритет и правило противоречий. Provenance выбранного значения MUST сохраняться. Противоречие MUST NOT закрываться молчаливой подменой одной метрики другой. Если приоритет или разбор противоречий не зафиксированы, dataset MUST NOT считаться успешно закрытым.

#### Scenario: Конфликт источников не закрывается молча

- **GIVEN** два допустимых источника dataset противоречат друг другу
- **AND** для dataset зафиксированы приоритет и разбор противоречий
- **WHEN** выбирается значение факта
- **THEN** выбор MUST следовать этим приоритету и разбору
- **AND** provenance MUST сохранять фактический источник
- **AND** одна метрика MUST NOT молча подменять другую

#### Scenario: Dataset без правила противоречия не закрыт

- **GIVEN** два допустимых источника dataset противоречат друг другу
- **WHEN** приоритет или разбор противоречий для dataset не зафиксированы
- **THEN** dataset MUST NOT считаться успешно закрытым источником

### Requirement: Источник товарных заказов и продаж остаётся открытым

Источник товарных заказов и продаж контура магазина остаётся открытым, пока нет evidence. Этот change MUST NOT назначать источник этой ленты и MUST NOT назначать supplier GET источником этого контура. Это не пожизненный запрет: будущее отдельное решение MAY выбрать источник по evidence. Заказы воронки MUST NOT автоматически заменять товарную ленту. Заказы рекламы, включая заказы внутри статистики кампании, MUST NOT автоматически заменять товарную ленту. Пока источник не назначен, dataset не считается закрытым воронкой, заказами рекламы или supplier GET. Неполнота остаётся явными `coverage` и `reason_codes`, а не тихим успехом. Identity семьи `ORDERS_OR_SALES_REPORTS_READ` этим требованием не назначается shop-контуру и не ослабляется.

#### Scenario: Источник ленты не назначен

- **GIVEN** evidence для выбора источника товарных заказов и продаж магазина ещё нет
- **WHEN** стратегия фиксирует этот dataset
- **THEN** источник MUST оставаться неназначенным
- **AND** supplier GET MUST NOT назначаться источником shop-контура этим change
- **AND** это MUST NOT читаться как пожизненный запрет: будущее отдельное решение MAY выбрать источник по evidence

#### Scenario: Воронка и заказы рекламы не заменяют товарную ленту

- **GIVEN** источник товарных заказов и продаж магазина не назначен
- **WHEN** доступны заказы воронки или заказы рекламы, включая заказы внутри статистики кампании
- **THEN** они MUST NOT автоматически заменять товарную ленту
- **AND** supplier GET MUST NOT закрывать эту ленту от имени этого change
- **AND** неполнота MUST оставаться явными `coverage` и `reason_codes`
- **AND** тихий успех MUST NOT подменять эту неполноту

#### Scenario: Identity operator-семьи не становится источником магазина

- **GIVEN** семья `ORDERS_OR_SALES_REPORTS_READ` сохраняет свою identity
- **WHEN** shop-контур AI Package фиксирует товарные заказы и продажи
- **THEN** эта identity MUST NOT назначаться источником shop-контура
- **AND** сама identity MUST NOT ослабляться

### Requirement: Граница стратегии источников

Эта capability фиксирует правила выбора источника. Она MUST NOT поставлять коллекторы, CSV poller, схему базы, экспортёр ZIP, запись в продукт, создание и управление кампаниями, JSON ответа AI, preview/apply и Telegram UI. Она MUST NOT переопределять формат документа и ZIP. Она MUST NOT переводить решение стратегии из предложенного в принятое и MUST NOT выбирать, какая физическая таблица хранит dataset. Непроверенные числовые потолки ранее прочитанного описания API MUST NOT становиться здесь нормативным окном сбора. Правило квалификации рабочей базы ClickHouse эта capability не меняет и SQL не пишет.

#### Scenario: Этот change не реализует контуры накопления и пакета

- **GIVEN** утверждена стратегия выбора источника
- **WHEN** проверяется, что именно поставлен этот change
- **THEN** коллекторы, CSV poller, схема базы, экспортёр ZIP, запись в продукт, создание и управление кампаниями, JSON ответа AI, preview/apply и Telegram UI MUST NOT считаться поставленными
- **AND** формат документа и ZIP MUST NOT переопределяться
- **AND** решение стратегии MUST оставаться предложенным
- **AND** физическая таблица dataset MUST NOT выбираться
