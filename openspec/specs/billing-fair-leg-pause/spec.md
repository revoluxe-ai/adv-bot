## Purpose

Ежедневное списание за paid авто-настройку MUST отражать реальную активность
ног комплекта: платная доля начисляется только за ноги в статусе «в работе»
на Wildberries, с защитой от обхода паузой перед списанием. Поведение
ортогонально pause-runtime (empty-keywords, полки, расписание, бюджет):
биллинг только читает итоговый статус ног, не меняя pause paths.

## Requirements

### Requirement: Participation gate by bot connection

Авто-настройка участвует в ежедневном биллинге только если бот подключён к
**якорной** записи комплекта (`bot_active` на стороне якоря). Связанная нога
комплекта MUST NOT самостоятельно открывать или закрывать участие в биллинге
через свой `bot_active`.

#### Scenario: Bot disconnected — no charge for the setup

- **GIVEN** авто-настройка с `bot_active` выключен на якорной записи
- **WHEN** наступает ежедневное списание за UTC-день
- **THEN** за эту авто-настройку MUST NOT начисляться платная доля (ни Auto-, ни Search-слот)

#### Scenario: Bot connected — setup enters billing

- **GIVEN** авто-настройка с `bot_active` включён на якорной записи
- **WHEN** система рассчитывает платную долю за UTC-день
- **THEN** авто-настройка MUST учитываться в расчёте кабинета (при прочих условиях слотов)

### Requirement: Anchor identity for auto-setting pair

Якорь авто-настройки MUST определяться структурной связью комплекта, а не
маркетинговым типом кампании на Wildberries (тип РК на WB может меняться).
Якорь — запись комплекта, у которой задана привязка `search_adv_id` на вторую
ногу; связанная нога — запись, чей идентификатор кампании совпадает с этой
привязкой. Если привязки нет или связанная нога не найдена, комплект
считается без Search-ноги для биллинга.

#### Scenario: Paired setup uses search_adv_id anchor

- **GIVEN** якорная запись с заданной привязкой на вторую ногу и существующей связанной записью комплекта
- **WHEN** система определяет состав слотов для биллинга
- **THEN** якорь MUST быть запись с привязкой; Search-слот MUST читать статус связанной ноги, а не наоборот

#### Scenario: Setup without Search link — anchor only

- **GIVEN** якорная запись с `bot_active` включён и без резолвящейся привязки на вторую ногу
- **WHEN** система рассчитывает слоты за UTC-день
- **THEN** Search-слот MUST отсутствовать; учитывается только якорный (первичный) слот комплекта

### Requirement: Per-leg daily slot weights

Для каждой участвующей в биллинге авто-настройки система MUST вести два
независимых биллинговых слота — **первичный (якорный)** и **Search** (если
нога есть). Каждый слот в статусе «в работе» (`started`) на Wildberries даёт
**половину** месячного тарифа за этот комплект за UTC-день; слот не в работе
даёт **ноль** за этот слот. Сумма слотов по комплекту: обе в работе → полный
тариф; одна → половина; ни одной → ноль за комплект в этот UTC-день.

#### Scenario: Both legs started — full tariff for setup

- **GIVEN** paid авто-настройка с ботом, парой ног, обе в статусе «в работе»
- **WHEN** система рассчитывает платную долю за UTC-день
- **THEN** сумма слотов за комплект MUST равняться полному тарифу (две половины)

#### Scenario: Only anchor leg started — half tariff

- **GIVEN** paid авто-настройка с ботом, Search-нога на паузе или не в работе, якорная нога в работе
- **WHEN** система рассчитывает платную долю за UTC-день
- **THEN** сумма слотов MUST равняться половине тарифа за комплект

#### Scenario: Only Search leg started — half tariff

- **GIVEN** paid авто-настройка с ботом и парой ног, Search в работе, якорная нога не в работе
- **WHEN** система рассчитывает платную долю за UTC-день
- **THEN** сумма слотов MUST равняться половине тарифа за комплект

#### Scenario: Both legs not in work — zero for setup

- **GIVEN** paid авто-настройка с ботом, обе ноги не в статусе «в работе»
- **WHEN** система рассчитывает платную долю за UTC-день
- **THEN** сумма слотов MUST быть ноль за этот комплект в этот UTC-день

#### Scenario: No Search leg but anchor in work — half tariff

- **GIVEN** paid авто-настройка с ботом без связанной Search-ноги, якорная нога в работе
- **WHEN** система рассчитывает платную долю за UTC-день
- **THEN** сумма слотов MUST равняться половине тарифа за комплект (только первичный слот)

### Requirement: Cabinet tariff tier from summed slot units

Ступень месячного тарифа кабинета MUST определяться по **сумме** платных
единиц слотов всех участвующих авто-настроек (каждая половина слота = 0.5
единицы; две половины = одна единица). Базовая таблица цен на авто-настройки
MUST NOT меняться этим требованием — меняется только учёт активных слотов.

#### Scenario: Two half-units equal one tier unit

- **GIVEN** кабинет с двумя авто-настройками, у каждой ровно одна нога в работе (по 0.5 единицы)
- **WHEN** система определяет ступень тарифа кабинета
- **THEN** эффективное количество единиц MUST быть 1.0 для ступени тарифа

### Requirement: UTC-day anti-gaming latch per leg

Система MUST NOT определять платную долю слота только по мгновенному статусу
ноги в секунду списания. За каждый UTC-день и каждый слот отдельно MUST
фиксироваться максимальная платная доля слота, достигнутая в этот UTC-день:
если нога хоть раз была «в работе» в UTC-день, слот MUST NOT обнуляться
паузой непосредственно перед списанием. Latch MUST NOT заменяться проверкой
только рубильника `bot_active` без учёта статуса ног.

#### Scenario: Pause before charge does not erase started leg same UTC-day

- **GIVEN** paid авто-настройка с ботом, Search-нога была «в работе» ранее в тот же UTC-день и поставлена на паузу непосредственно перед списанием
- **WHEN** выполняется ежедневное списание за этот UTC-день
- **THEN** Search-слот MUST учитываться как половина тарифа за комплект (не ноль)

#### Scenario: Leg never started whole UTC-day — slot stays zero

- **GIVEN** paid авто-настройка с ботом, Search-нога не была «в работе» ни разу в UTC-день
- **WHEN** выполняется ежедневное списание
- **THEN** Search-слот MUST быть ноль за этот UTC-день

### Requirement: Separate daily charge records per leg slot

За каждую авто-настройку и UTC-день система MUST создавать **отдельные**
записи списания для первичного (якорного) слота и Search-слота (если слот
billable > 0), привязанные к якорной записи комплекта. MUST NOT агрегировать
оба слота в одну неразличимую строку «за РК» без указания слота.

#### Scenario: Two leg lines when both slots billable

- **GIVEN** оба слота billable за UTC-день (сумма = полный тариф)
- **WHEN** списание зафиксировано в данных
- **THEN** MUST существовать отдельная запись для первичного слота и отдельная для Search-слота

#### Scenario: One leg line when only one slot billable

- **GIVEN** billable только первичный слот (половина тарифа)
- **WHEN** списание зафиксировано
- **THEN** MUST существовать запись только для billable слота; второй слот MUST NOT создавать нулевую запись-дубликат

### Requirement: Backward-compatible full charge baseline

Когда обе ноги комплекта в работе весь релевантный UTC-день, итоговая сумма
списания за комплект MUST совпадать с действующим до change поведением
(полный тариф за авто-настройку). Грация, дедупликация «одно списание за
UTC-день», режимы тарифа кабинета и блокировка при недостатке средств MUST
сохранить прежнюю семантику на уровне кабинета. Чтение исторических записей
списания до разделения по слотам MUST NOT ломать отчёты и повторные прогоны
списания.

#### Scenario: Full-active setup matches legacy daily total

- **GIVEN** авто-настройка, которая до change оплачивалась как одна единица при подключённом боте, обе ноги в работе
- **WHEN** выполняется списание за UTC-день после внедрения fair leg-pause billing
- **THEN** суммарная сумма за комплект MUST равняться прежнему полному дневному тарифу за эту настройку

#### Scenario: Legacy charge records remain readable

- **GIVEN** в истории есть записи списания за UTC-день без разделения по слотам (до change)
- **WHEN** система формирует отчёт или проверяет повторное списание
- **THEN** legacy-записи MUST учитываться без ошибки; новое разделение MUST NOT трактовать их как «не списано»

### Requirement: Billing does not drive pause runtime

Списание и latch MUST NOT инициировать паузу/запуск кампаний на Wildberries и
MUST NOT менять pause reasons. Изменение платной доли MUST быть следствием
уже существующего статуса ног (в т.ч. после pause-runtime empty-keywords,
shelf-exhausted, расписания, бюджета).

#### Scenario: Search paused by empty-keywords reduces Search slot only

- **GIVEN** Search-нога на паузе из-за empty-keywords, якорная нога в работе, бот подключён
- **WHEN** выполняется расчёт списания
- **THEN** платная доля MUST отражать паузу Search (половина тарифа за комплект), и система MUST NOT возобновлять Search ради биллинга

### Requirement: Observable lifecycle coverage (UTC-day billing)

Материальные переходы fair leg-pause billing MUST быть покрыты сценариями
выше: gate по боту → определение якоря → вес слотов → latch за UTC-день →
ступень тарифа кабинета → списание кабинета → раздельные записи по слотам.
Отдельный user-facing сценарий для «только preview тарифа в UI» MAY быть
добавлен в том же change, но MUST NOT менять правила списания.

#### Scenario: End-to-end half charge when one leg paused all day without prior started

- **GIVEN** бот подключён, пара ног, Search не была «в работе» весь UTC-день, якорная в работе, latch не повышает Search-слот
- **WHEN** списание за UTC-день завершено
- **THEN** кабинет списан за половину тарифа комплекта; одна billable строка по первичному слоту
