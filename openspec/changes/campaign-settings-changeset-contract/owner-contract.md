# Owner Contract

## Что хотим получить

Канонический версионированный пакет изменений настроек кампании `ChangeSetV1`:
кто предложил изменение, какую кампанию и какую ногу Auto или Search оно
затрагивает, какое поле и какое значение просит, и какое текущее значение
ожидает увидеть. Пакет проходит одну и ту же проверку независимо от того,
пришёл он из JSON, будущего API или MCP. На выходе только один из трёх
результатов: изменений нет, есть точный diff, либо весь пакет отклонён.
Запись в Wildberries, базу или Excel этот пакет не выполняет.

## Зачем

Сейчас поля настроек уже классифицированы, но намерение что-то изменить
не является контрактом. Модель может описать желание, а решение о записи
должно оставаться за WB Sky и только после детерминированной проверки.
Неизвестное поле, неизвестная возможность кабинета, устаревшее текущее
значение или смесь верных и неверных операций не должны проходить частично.

## Что должно остаться неизменным

Текущие настройки по-прежнему читаются из PostgreSQL. История в ClickHouse
и Excel остаются проекциями уже принятого реестра полей, а не протоколом
управления. Существующие записи настроек из бота, Excel и shop-runner в этом
изменении не переписываются. Рекламная логика ставок и жизненный цикл
кампаний в проде не меняются.

## Чего сейчас не делаем

Не пишем в WB API, PostgreSQL, ClickHouse. Не делаем apply, согласование,
журнал событий, проверку после записи, MCP, публичный API, экран Telegram
и переделку Excel. Не подключаем полный AI Package. Не строим постоянное
хранилище идемпотентности и распределённые блокировки.

## Как поймём, что получилось

Один валидный пакет по одному полю даёт diff со старым, запрошенным и
нормализованным значением. Пакет без фактической разницы даёт «без изменений».
Неподдерживаемое поле, поле только для чтения, плохое значение, неизвестная
capability, неподдерживаемый тип кампании, чужое ожидаемое значение,
отсутствие текущего снимка, повтор operation id и смесь годных и негодных
операций отклоняют пакет целиком. Auto и Search не склеиваются в одну цель.
Повторный одинаковый changeset id не создаёт вторую запись, потому что
записи нет вообще.

## Решения Owner

Модель создаёт только намерение. WB Sky остаётся владельцем решения.
Модель сама не принимает production-write решение. Любая внешняя мутация
в будущем обязана пройти детерминированную проверку. Неизвестное и
неподдерживаемое закрывается отказом. Контракт не зависит от транспорта.
JSON, API и MCP используют одну семантику. Excel не является каноническим
протоколом управления. Сложные межполевые правила не живут только в JSON
Schema. Повторно используем реестр настроек, а не второй ручной список полей.
