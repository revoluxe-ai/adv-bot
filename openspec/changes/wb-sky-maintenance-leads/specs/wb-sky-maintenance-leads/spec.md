## ADDED Requirements

### Requirement: Режим обслуживания WB Sky исключает рекламные операции
В режиме обслуживания WB Sky MUST показывать пользователю согласованное уведомление об обновлении и единственное действие «📩 Оставить заявку». Все прежние пользовательские команды и кнопки MUST NOT запускать операции управления рекламой, фоновые изменения ставок, бюджетов, ключей или жизненного цикла кампаний.

#### Scenario: Вход пользователя
- **GIVEN** бот работает в режиме обслуживания
- **WHEN** пользователь отправляет `/start` или команду с параметром
- **THEN** бот показывает уведомление об обновлении и возможность оставить заявку
- **AND** не выполняет рекламные write-действия

#### Scenario: Старая inline-кнопка
- **GIVEN** пользователь сохраняет старое сообщение с кнопками рекламы
- **WHEN** пользователь нажимает старую кнопку
- **THEN** бот отвечает на callback и показывает режим обслуживания
- **AND** никаких рекламных операций не выполняется

### Requirement: Заявка требует подтверждённого формата номера телефона
Бот MUST запрашивать номер через встроенную передачу собственного контакта Telegram или через ручной ввод. Невалидный номер либо контакт, не соответствующий идентификатору отправителя, MUST NOT считаться завершённой заявкой.

#### Scenario: Собственный контакт
- **GIVEN** пользователь выбрал «📩 Оставить заявку»
- **WHEN** Telegram передаёт номер с идентификатором этого пользователя
- **THEN** бот нормализует допустимый номер и начинает доставку заявки владельцу

#### Scenario: Ввод номера вручную
- **GIVEN** пользователь сообщает телефон в допустимом международном формате
- **WHEN** номер проходит проверку
- **THEN** бот начинает доставку заявки владельцу

#### Scenario: Чужой контакт или некорректный номер
- **WHEN** пользователь отправляет чужой контакт или невалидное значение
- **THEN** бот предлагает повторить ввод
- **AND** не сообщает об успешной заявке

### Requirement: Получатель — владелец из действующего реестра администраторов
Заявка MUST направляться только владельцу, определённому существующей конфигурацией WB Sky. Неоднозначное определение владельца MUST приводить к отказу от отправки, а не к доставке другому администратору.

#### Scenario: Определён единственный владелец
- **GIVEN** действующая конфигурация подтверждает владельца
- **WHEN** корректная заявка подготовлена
- **THEN** уведомление с именем, нормализованным телефоном, Telegram username, Telegram ID и временем направляется владельцу

#### Scenario: Несогласованная конфигурация
- **GIVEN** конфигурация идентификатора владельца отсутствует либо противоречит реестру
- **WHEN** процесс начинает работу
- **THEN** он MUST завершиться безопасно и MUST NOT направлять заявки произвольному получателю

### Requirement: Подтверждение пользователю следует только за доставкой владельцу
Бот MUST сообщать «заявка принята» только после подтверждённого ответа Telegram API на отправку владельцу. Если отправка владельцу неуспешна, завершение заявки MUST NOT подтверждаться. Повторная доставка допускается, а уведомление MUST включать идентификатор update для обнаружения дублей.

#### Scenario: Успешная доставка владельцу
- **WHEN** Telegram API подтвердил отправку номера владельцу
- **THEN** пользователь получает подтверждение заявки

#### Scenario: Ошибка доставки владельцу
- **WHEN** Telegram API не подтвердил отправку
- **THEN** пользователь не получает ложное сообщение об успешной заявке
- **AND** система сохраняет возможность повторной обработки update

### Requirement: Режим обслуживания не зависит от рекламных хранилищ
Сценарий уведомления и приёма заявок MUST работать без доступности PostgreSQL WB Sky, ClickHouse, Redis и Wildberries API, с единственным активным потребителем Telegram обновлений на токен.

#### Scenario: Остановленные базы и рекламные воркеры
- **GIVEN** серверы данных WB Sky и рекламные воркеры остановлены
- **WHEN** пользователь открывает бота и отправляет допустимый телефон
- **THEN** приложение способно обработать и доставить заявку через Telegram

#### Scenario: Переключение режима
- **WHEN** оператор переводит WB Sky в режим обслуживания
- **THEN** старый и новый Telegram poller MUST NOT работать параллельно с одним токеном
- **AND** сохранён проверяемый путь отката конфигурации
