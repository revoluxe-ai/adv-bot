## 2. Domain aggregation

- [ ] 2.1 Вынести использование существующих границ окон в доменный сервис анализа внутри `ai_package_v1`. Сервис MUST оставаться read-only. ZIP assembler MUST NOT получить формулы.
- [ ] 2.2 Чтение `default_db.full_adv_wb_stat` для окон MUST квалифицировать базу и MUST брать последнюю версию на ногу и день на диапазоне окон, а не на узком периоде вызывающей стороны.
- [ ] 2.3 Если день или метрика отсутствуют, сервис MUST NOT писать ноль. Если источник наблюдал ноль, значение MUST остаться нулём. Если семейство GAP, метрики семейства MUST быть невычислимы.
- [ ] 2.4 Если у комплекса два физических идентификатора, витрина MUST содержать две строки. Магазинная сумма MAY существовать только как помеченная производная distinct ног.
- [ ] 2.5 Если фактов атрибуции нет, заказы кампании MUST остаться в области статистики кампании. Прямые и связанные CPO/DRR MUST быть невычислимы. Если связанная область не доказана, сервис MUST NOT подставить прямую. Если доказана только одна нога, сервис MUST NOT копировать её в другую.
- [ ] 2.6 Если выручка магазина или полнота расхода магазина не доказаны, DRR магазина MUST быть невычислим и MUST NOT использовать рекламную сумму заказов как выручку магазина.
- [ ] 2.7 Сырые дневные строки MUST NOT дублироваться по числу окон. Второй файл ключевых окон MUST NOT создаваться.
- [ ] 2.8 Сравнения MUST получать статус сопоставимо, частично или несопоставимо. Если знаменатель наблюдаемый ноль, статус MUST быть несопоставимо. Если покрытие частичное при той же семантике, статус MUST быть частичным. Вложенные горизонты MUST быть помечены как вложенные.
