## ADDED Requirements

### Requirement: Оперативный сбор, backfill и CSV — разные режимы

Оперативный сбор, исторический backfill и асинхронные CSV-отчёты MUST быть разными режимами. Оперативный тик закрывает только то окно, которое выбранный метод реально возвращает. Backfill ведёт свой курсор и не является тем же оперативным запросом. CSV — отдельное асинхронное ожидание готовности задания.

#### Scenario: Три режима не смешиваются

- **GIVEN** dataset нуждается и в свежем окне, и в более длинной истории
- **WHEN** выбирается способ получить данные
- **THEN** оперативный сбор, исторический backfill и асинхронный CSV MUST оставаться разными режимами
- **AND** backfill MUST NOT представляться тем же оперативным запросом
- **AND** CSV MUST NOT представляться тем же оперативным запросом

#### Scenario: Оперативный тик закрывает только реальное окно метода

- **GIVEN** выбран метод оперативного сбора
- **WHEN** выполняется оперативный тик
- **THEN** тик MUST запрашивать только окно, которое этот метод реально возвращает

#### Scenario: Backfill ведёт собственный курсор

- **GIVEN** для dataset допустим исторический backfill
- **WHEN** backfill продолжается
- **THEN** он MUST вести собственный курсор
- **AND** MUST NOT быть тем же оперативным запросом

### Requirement: Период одного запроса не расширяется

Ограничение API MUST NOT обходиться увеличением периода одного запроса. CSV MUST NOT подменяться тем же оперативным запросом на больший период. Догоняющий один запрос на весь пропущенный период восстановлением не является.

#### Scenario: Короткое окно не растягивается

- **GIVEN** выбранный метод реально возвращает окно короче нужной истории
- **WHEN** оперативный запрос готовится
- **THEN** период этого запроса MUST NOT увеличиваться, чтобы обойти ограничение API

#### Scenario: CSV не заменяется более длинным оперативным запросом

- **GIVEN** длинная история dataset допустима только асинхронным CSV
- **WHEN** ожидается готовность CSV
- **THEN** ожидание MUST NOT заменяться оперативным запросом на больший период

#### Scenario: Весь пропуск одним запросом не восстанавливается

- **GIVEN** после простоя известен пропущенный интервал длиннее окна метода
- **WHEN** предлагается один оперативный запрос на весь этот интервал
- **THEN** такой запрос MUST NOT считаться восстановлением
- **AND** период одного оперативного запроса MUST NOT увеличиваться

### Requirement: История длиннее окна — отдельный режим или явный разрыв

Если dataset нужна история длиннее оперативного окна и для неё есть допустимый отдельный режим, история MUST идти этим режимом. Если допустимого режима нет, dataset остаётся неполным: явный разрыв с периодом и `reason_codes`. Несколько `reason_codes` MAY действовать сразу. В обеих ветках период одного оперативного запроса не расширяется. Успешный оперативный тик эту историю полной не делает.

#### Scenario: Длинная история идёт допустимым отдельным режимом

- **GIVEN** dataset нужна история длиннее оперативного окна
- **AND** для неё есть допустимый backfill или CSV
- **WHEN** история добирается
- **THEN** она MUST идти этим отдельным режимом
- **AND** период одного оперативного запроса MUST NOT увеличиваться
- **AND** успешный оперативный тик MUST NOT делать эту историю полной

#### Scenario: Нет допустимого режима — явный разрыв

- **GIVEN** dataset нужна история длиннее оперативного окна
- **AND** допустимого backfill или CSV для неё нет
- **WHEN** фиксируется результат накопления
- **THEN** dataset MUST оставаться неполным
- **AND** MUST сохраниться явный разрыв с периодом и `reason_codes`
- **AND** несколько `reason_codes` MAY действовать сразу
- **AND** период одного оперативного запроса MUST NOT увеличиваться
- **AND** успешный оперативный тик MUST NOT делать эту историю полной

### Requirement: CSV ждёт готовность задания

Асинхронный CSV MUST быть третьим режимом. Контур MUST ждать готовность задания. Ожидание MUST NOT заменяться оперативным запросом на больший период. Продолжение CSV MUST быть ожиданием той же асинхронной задачи, а не новым расширенным оперативным запросом.

#### Scenario: Контур ждёт готовность CSV

- **GIVEN** для dataset запущен асинхронный CSV-отчёт
- **WHEN** отчёт ещё не готов
- **THEN** контур MUST ждать готовность этого задания
- **AND** ожидание MUST NOT заменяться оперативным запросом на больший период
- **AND** продолжение MUST относиться к той же асинхронной задаче

### Requirement: После простоя восстанавливается пропущенный интервал

После простоя пропущенный интервал MUST быть определён. Если оперативный API не восстанавливает старые дни, история MUST идти допустимым для этого dataset режимом backfill или CSV. Если восстановление невозможно, MUST сохраняться явный разрыв с периодом и причиной. Успешный следующий оперативный тик MUST NOT делать историю полной.

#### Scenario: Пропущенный интервал определяется

- **GIVEN** оперативный сбор магазина простоял
- **WHEN** контур сбора снова работает
- **THEN** пропущенный интервал MUST быть определён
- **AND** определение интервала MUST NOT пропускаться из-за того, что следующий оперативный тик успешен

#### Scenario: Старые дни добираются допустимым backfill или CSV

- **GIVEN** пропущенный интервал определён
- **AND** оперативный API не восстанавливает эти старые дни
- **AND** для dataset есть допустимый backfill или CSV
- **WHEN** история восстанавливается
- **THEN** добор MUST идти этим допустимым режимом
- **AND** период одного оперативного запроса MUST NOT увеличиваться
- **AND** успешный следующий оперативный тик MUST NOT делать историю полной

#### Scenario: Невозможное восстановление оставляет явный разрыв

- **GIVEN** пропущенный интервал определён
- **AND** оперативный API не восстанавливает старые дни
- **AND** допустимый backfill или CSV восстановить этот интервал не может
- **WHEN** контур фиксирует результат
- **THEN** MUST сохраниться явный разрыв с периодом и причиной
- **AND** успешный следующий оперативный тик MUST NOT делать эту историю полной

### Requirement: Непроверенные числовые потолки не нормативны

Непроверенные числовые потолки ранее прочитанного описания API MUST NOT записываться как нормативный MUST оперативного окна. Окно оперативного режима — то, которое выбранный метод реально возвращает.

#### Scenario: Ранее прочитанный потолок не становится окном

- **GIVEN** числовой потолок периода ранее читался в описании API и живым порталом не подтверждён
- **WHEN** задаётся оперативное окно dataset
- **THEN** этот потолок MUST NOT становиться нормативным MUST окна
- **AND** оперативное окно MUST быть тем, которое выбранный метод реально возвращает

### Requirement: Новые фоновые задачи не вытесняют production collectors

Новые фоновые задачи MUST NOT нарушать лимиты WB API и MUST NOT вытеснять работающие production collectors. Это требование не превращает непроверенные числовые потолки в обязательное окно сбора.

#### Scenario: Новая фоновая задача не ломает лимит и не вытесняет сбор

- **GIVEN** работают production collectors магазина
- **WHEN** ставится новая фоновая задача накопления
- **THEN** она MUST NOT нарушать лимиты WB API
- **AND** MUST NOT вытеснять работающие production collectors
- **AND** непроверенный числовой потолок MUST NOT становиться из-за этого обязательным окном

### Requirement: Граница режимов накопления

Эта capability фиксирует различие режимов и восстановление после простоя. Она MUST NOT поставлять оперативные коллекторы, исполняемый backfill, CSV poller, схему базы, экспортёр ZIP, запись в продукт, создание и управление кампаниями, JSON ответа AI, preview/apply и Telegram UI. Она MUST NOT задавать процедуру обнаружения кампаний вне инвентаря и MUST NOT переопределять формат ZIP. Решение стратегии MUST оставаться предложенным.

#### Scenario: Режимы описаны без поставки исполняемого сбора

- **GIVEN** зафиксированы оперативный сбор, backfill и CSV
- **WHEN** проверяется поставка этого change
- **THEN** оперативные коллекторы, исполняемый backfill, CSV poller, схема базы, экспортёр ZIP, запись в продукт, создание и управление кампаниями, JSON ответа AI, preview/apply и Telegram UI MUST NOT считаться поставленными
- **AND** процедура обнаружения кампаний вне инвентаря MUST NOT задаваться
- **AND** формат ZIP MUST NOT переопределяться
- **AND** решение стратегии MUST оставаться предложенным
