# Owner Contract

## Что хотим получить

Зафиксировать и доказать, что **старый** и **новый** модули управления ставкой Авто не конфликтуют.

Как в интерфейсе настроек РК:

- **Старый модуль:** главное меню РК → **«Управление ставкой»** → **«Включить управление ставкой для Авто»** (выкл — «Выключить управление ставкой для Авто»).
- **Новый модуль:** главное меню РК → **«Управление ставкой в полках»** (там «Включить управление» / «Выключить управление»).

Правило: **если новый модуль включён — старый игнорируется** (не меняет ставку Авто). Если новый выключен — старый может работать (когда «управление ставкой для Авто» включено). 

Причины паузы/старта и записи ставок остаются различимыми. Коротко описать контракт — **без** переписывания алгоритмов выбора ставки / plan_distance.

## Где старое, где новое

**Старое**

1. В главном меню настроек РК нажать **«Управление ставкой»**.
2. На открывшемся экране — **«Включить управление ставкой для Авто»** / **«Выключить управление ставкой для Авто»**.

Это и есть старый модуль управления ставкой Авто.

**Новое**

1. В том же главном меню настроек РК — кнопка **«Управление ставкой в полках»** (ниже «Управление ставкой»).
2. На экране полок — **«Включить управление»** / **«Выключить управление»**.

Это новый модуль.

**Соседство**

1. В **«Управление ставкой в полках»** нажали **«Выключить управление»**  
   → ставку Авто может менять старый путь: **«Управление ставкой» → «Включить управление ставкой для Авто»**  
   → **«Управление ставкой в полках»** ставку не меняет.

2. В **«Управление ставкой в полках»** нажали **«Включить управление»**  
   → ставку меняет только **«Управление ставкой в полках»**  
   → **«Управление ставкой для Авто»** (старый модуль) **игнорируется** — ставку не меняет.

**Не путать с соседними кнопками**

- Другие кнопки внутри «Управление ставкой» (авто-CPM, макс. ставка, шаг, целевая позиция) — не эта пара конфликта; конфликт про **ставку Авто**: «для Авто» ↔ «в полках».
- «Переключить на кластерный / стандартный биддер (CPM)» — другая настройка.
- «Включить/Выключить контроль активности кампании» — пауза/старт, не запись ставки.
- Режим раскрутки РС (полок) — отдельно.

**Ещё не существует**

- Будущая пауза «полки исчерпаны / нет плана» — не этот шаг; не маскировать под `cost_rule_failed`.
- Пауза Search по пустым ключам — другой путь.

## Зачем

Скоро понадобится честная пауза «ставки в полках исчерпаны». Сначала нужно быть уверенными: когда **«Управление ставкой в полках»** включено, старое «управление ставкой для Авто» не дерётся с ним за ставку.

## Что должно остаться неизменным

- «Управление ставкой в полках» выкл + «управление ставкой для Авто» вкл: старый путь работает как раньше.
- «Управление ставкой в полках» вкл: новый путь меняет ставку; старый («для Авто») игнорируется.
- Hold freeze ≠ остановка кампании.
- Search «пустые ключи» не трогаем.
- Не переписываем логику выбора ставки полок и plan_distance «заодно».

## Чего сейчас не делаем

- Терминальную паузу полок «ставки исчерпаны / нет плана» и отложенный перетест.
- Search empty-keywords, биллинг ног, тариф 1000₽, коммуникации, disconnect, onboarding.
- Выпил updater v2.
- Новый reason в БД под shelf-exhausted.

## Как поймём, что получилось

- Доказано: «Управление ставкой в полках» вкл → «управление ставкой для Авто» ставку не меняет; выкл → «Управление ставкой в полках» ставку не меняет, старый путь может.
- Тесты на оба режима; причины различимы.
- Будущую паузу полок нельзя спрятать под `cost_rule_failed`.

## Решения Owner

- Старый модуль в UI: **«Управление ставкой» → «Включить управление ставкой для Авто»**.
- Новый модуль в UI: главное меню РК → **«Управление ставкой в полках»**.
- Если новый включён — старый **игнорируется**.
- Без rewrite selection/plan_distance и без терминального retest.
- Будущую терминальную причину полок нельзя маскировать под `cost_rule_failed`.
- Hold freeze ≠ stop; Search empty-keywords ортогонален.
