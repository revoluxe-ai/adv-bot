## 2. Domain aggregation

- [x] 2.1 Вынести использование существующих границ окон в доменный сервис анализа внутри `ai_package_v1`. Сервис MUST оставаться read-only. ZIP assembler MUST NOT получить формулы.
- [x] 2.2 Чтение `default_db.full_adv_wb_stat` для окон MUST квалифицировать базу и MUST брать последнюю версию на ногу и день на диапазоне окон, а не на узком периоде вызывающей стороны.
- [x] 2.3 Если день или метрика отсутствуют, сервис MUST NOT писать ноль. Если источник наблюдал ноль, значение MUST остаться нулём. Если семейство GAP, метрики семейства MUST быть невычислимы. Если `source_complete_through` раньше номинального конца, окно MUST NOT получать `COMPLETE` только из-за `package_cutoff_date`.
- [x] 2.4 Если у комплекса два физических идентификатора, витрина MUST содержать две строки. Сумма ног пакета MAY существовать только как `PACKAGE_CAMPAIGN_SCOPE`. Если полный охват кампаний магазина не доказан, `ALL_SHOP_AD_SPEND` и `SHOP_AD_SPEND` MUST быть невычислимы.
- [x] 2.5 Если фактов атрибуции нет, заказы кампании MUST остаться в области статистики кампании. Прямые и связанные CPO/DRR MUST быть невычислимы. Если связанная область не доказана, сервис MUST NOT подставить прямую. Если доказана только одна нога, сервис MUST NOT копировать её в другую.
- [x] 2.6 DRR магазина MUST быть невычислим, пока не доказаны оба входа: весь рекламный расход магазина и фактическая выручка магазина. Расход `PACKAGE_CAMPAIGN_SCOPE` MUST NOT подставляться в числитель. Рекламная сумма заказов MUST NOT подставляться в знаменатель.
- [x] 2.9 Строка артикула MUST нести `KEYWORD_PERFORMANCE_PRODUCT_SCOPE`. Если нет источника всех продаж артикула, вся выручка артикула и DRR артикула MUST быть невычислимы. Файл MUST NOT называться так, будто это вся экономика товара.
- [x] 2.7 Сырые дневные строки MUST NOT дублироваться по числу окон. Второй файл ключевых окон MUST NOT создаваться.
- [x] 2.8 Сравнения MUST получать статус сопоставимо, частично или несопоставимо. Если знаменатель наблюдаемый ноль, статус MUST быть несопоставимо. Если покрытие частичное при той же семантике, статус MUST быть частичным. Вложенные горизонты MUST быть помечены как вложенные.
