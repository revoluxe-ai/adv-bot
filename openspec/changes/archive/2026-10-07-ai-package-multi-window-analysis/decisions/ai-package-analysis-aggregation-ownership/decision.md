# Decision: Владелец аналитической агрегации AI Package

## Status

Proposed

## Context

Экспорт AI Package уже отделён от коллекторов и shop-runner. Каталог окон живёт у ключевой истории. Постановка многогоризонтного анализа требует тех же границ и формул для магазина, физической ноги и будущих транспортов API/MCP. Если формулы останутся в сборщике ZIP, транспорты разойдутся, а модель начнёт сама додумывать арифметику.

Принятые решения закрывают read-only границу экспорта и запрет слияния Auto/Search, но не называют единого владельца оконных метрик вне ключевого файла.

## Decision

1. Смысл аналитических окон, метрик, покрытия и сопоставимости MUST принадлежать одному доменному сервису внутри `app/modules/ai_package_v1/`.
2. Границы стандартных дневных и календарных окон MUST совпадать с уже принятым каталогом ключевых окон. Номинальный конец MUST быть `package_cutoff_date` (UTC-дата сборки минус один день). Эта граница MUST NOT называться полнотой источника. Второй каталог скользящих 24 часов MUST NOT появляться. Часовой пояс отчётности WB MUST оставаться неизвестным, пока источник его не докажет.
3. Сборщик ZIP MUST только кодировать уже посчитанные доменные payload. API и MCP MUST быть адаптерами того же результата и MUST NOT вводить собственные формулы.
4. LLM MUST NOT быть источником фактических метрик.
5. Сервис MUST оставаться `READ_ONLY_NO_MUTATION` по правилам экспортного решения.
6. Прямая и связанная атрибуция MUST NOT выпускаться числом без фактов атрибуции. Тихий откат между ними MUST NOT существовать.
7. Сумма ног пакета MUST называться охватом пакета. Расход всего магазина MUST NOT выпускаться без доказательства полного охвата кампаний магазина. DRR магазина MUST NOT выпускаться, пока не доказаны и этот расход, и фактическая выручка магазина. Расход охвата пакета MUST NOT подставляться в DRR магазина.
8. Строка артикула из ключевой истории MUST нести область этого зерна и MUST NOT изображать всю экономику артикула.
9. Новая таблица агрегатов MUST NOT создаваться этим правилом. Её можно предложить только отдельным change после измерения.

## Applies to

- Аналитический слой Full AI Package
- Будущие API и MCP чтения тех же окон
- Не применяется к биддеру и к записи в WB

## Allowed

- Вызов доменного сервиса из существующего экспортного сервиса до кодирования ZIP
- Переиспользование каталога окон и уже посчитанной ключевой витрины
- Read-only чтение `default_db.full_adv_wb_stat` на диапазоне окон с квалификацией базы в тексте SQL
- Явная производная сумма физических ног, вошедших в пакет, с областью охвата пакета
- Резерв идентификаторов невычислимых метрик

## Forbidden

- Формулы метрик в сборщике ZIP, в обработчике MCP или в тексте инструкции как единственной норме
- Копия сырых строк на каждое окно
- Слияние Auto и Search
- Подмена пропусков нулями
- Поле, которое называет границу пакета последним полным днём источника
- Имена расхода всего магазина без полного охвата кампаний
- Подстановку расхода пакета в DRR магазина
- Товарную витрину без области ключевой истории
- Объявление кампанийных заказов прямой или связанной атрибуцией
- Запуск коллектора или WB API ради заполнения окна
- Изменение фиксированного CPO и включение динамического DRR в этом решении

## Examples

Хорошо: экспортный сервис получает строки окон от доменного сервиса и передаёт их в уже существующий кодировщик ZIP.

Плохо: сборщик архива сам суммирует CSV и называет результат связанным DRR. Плохо: MCP считает CPO иначе, чем ZIP.
