## Why

ChatGPT должен читать данные конкретного продавца WB Sky по удалённому MCP, не получая второй аналитический контракт и не получая право менять рекламу. Сейчас у WB Sky нет OAuth и нет MCP: человек работает через Telegram-бота, а Full AI Package собирается read-only экспортёром.

## What Changes

- Появляется read-only MCP transport над уже существующими read-моделями WB Sky.
- Появляется мост OAuth 2.1 Authorization Code + PKCE: протокол на backend, согласие человека в существующем Telegram-боте, без сайта логина.
- Инструменты первой версии: профиль, список магазинов, возможности магазина, AI-пакет.
- Доступ к магазину проверяется на каждом вызове по текущей связи пользователя и кабинета.
- Отключение ChatGPT в боте сразу лишает токен силы.

## Capabilities

### New Capabilities

- `wb-sky-mcp-read-interface`: удалённое чтение профиля, магазинов, возможностей и AI-пакета для уже авторизованного принципала WB Sky, плюс граница «записи нет».

### Modified Capabilities

- Нет. Требования Full AI Package и экспортёра не переписываются. MCP только показывает их результат.

## Impact

- Новый транспорт и OAuth-конечные точки в существующем FastAPI-процессе бота. Отдельный сервис не нужен.
- Короткоживущие OAuth-транзакции в уже существующем Redis.
- Долговечные подключения ChatGPT и refresh-токены в PostgreSQL, рядом с уже существующим пользователем. Миграции в этом планировании не создаются.
- Бот получает сценарий подтверждения и отключения. Токен бота и Telegram user id не становятся ключом MCP.
- Экспорт по-прежнему читает накопленные данные и не вызывает запись в WB.
- ChangeSet, PR #449 и PR #450 этим change не меняются.
