# Правила проверки и анализа кода

## Принципы анализа кода:

### 1. Проверка актуальности и использования:
- **Всегда проверяй, используется ли код** - если файл выглядит подозрительно, сначала убедись что он нужен
- Используй `grep_code` для поиска импортов модуля
- Если модуль нигде не импортируется - кандидат на удаление
- Особое внимание на тесты - часто импортируют несуществующие функции

### 2. Признаки проблемного кода:
- Много закомментированного кода
- Импорты несуществующих модулей/функций
- Неиспользуемые переменные (F841 в ruff)
- Функции без типов (mypy warnings)
- Циклические импорты (import-linter violations)

### 3. Архитектурные проверки:
- Соблюдение слоев архитектуры
- Отсутствие циклических зависимостей
- Правильное использование абстракций
- Разделение ответственности между модулями

## Процесс review:

### 1. Статический анализ:
- Запуск всех pre-commit хуков
- Проверка mypy на типы
- Проверка ruff на качество кода
- Проверка import-linter на архитектуру

### 2. Функциональная проверка:
- Все тесты проходят
- Функциональность не сломана
- API совместимость сохранена
- Производительность не ухудшилась

### 3. Качество изменений:
- Логичность коммитов
- Полнота описания изменений
- Соответствие стандартам проекта
- Отсутствие технического долга

## Типичные проблемы и решения:

### Устаревший код:
```python
# Проблема: тест импортирует несуществующий класс
from module import NonExistentClass  # ImportError

# Решение: проверить актуальность теста
grep_code "NonExistentClass"  # если не найдено - удалить тест
```

### Неиспользуемые переменные:
```python
# Проблема:
with patch("func") as mock_func:  # F841: assigned but never used
    result = call_function()

# Решение: убрать присваивание
with patch("func"):
    result = call_function()
```

### Циклические импорты:
```python
# Проблема: A -> B -> A
# module_a.py
from module_b import function_b

# module_b.py
from module_a import function_a

# Решение: вынести общие части в отдельный модуль
```

## Автоматизация:

### Pre-commit хуки:
- black (форматирование)
- ruff (линтинг)
- mypy (типы)
- import-linter (архитектура)

### Команды для проверки:
```bash
# Полная проверка
pre-commit run --all-files

# Только архитектура
pre-commit run import-linter

# Очистка кэша при проблемах
pre-commit clean
```

## Критерии качества:

### Обязательные:
- ✅ Все pre-commit хуки проходят
- ✅ Тесты проходят
- ✅ Нет циклических импортов
- ✅ Типы корректны (mypy)

### Желательные:
- ✅ Покрытие тестами
- ✅ Документация обновлена
- ✅ Производительность не ухудшена
- ✅ Технический долг уменьшен
