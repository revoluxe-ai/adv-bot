# Конфигурация логирования Fluent Bit

Эта директория содержит конфигурационные файлы для Fluent Bit, используемого для сбора, обработки и пересылки логов в Kubernetes-кластере.

## Содержание:

*   **Файлы `.yaml`**: Находятся непосредственно в директории `k8s\\logging\\`. Это Kubernetes-манифесты (ConfigMaps, DaemonSets и т.д.), которые определяют, как Fluent Bit развертывается и конфигурируется в кластере. Они включают в себя:
    *   `fluent-bit-errors-to-webhook.yaml`: Конфигурация для пересылки ошибок (определенных по ключевым словам в логах) на внешний HTTP-эндпоинт.
    *   `fluent-bit-cm-*.yaml`: ConfigMaps, содержащие различные версии конфигурации Fluent Bit.
    *   `fluent-bit-direct.yaml`: ... (необходимо добавить описание для этого файла, если его назначение известно)

*   **Директория `fluent-bit-configs\`**: Содержит основные конфигурационные файлы Fluent Bit (`.conf`) и вспомогательные файлы (например, `.json`). Эти файлы определяют:
    *   Источники логов (Input): откуда Fluent Bit будет собирать логи (например, из контейнеров Kubernetes, системных журналов).
    *   Фильтры (Filter): как логи будут обрабатываться, обогащаться метаданными (например, Kubernetes-метаданными), переписываться или фильтроваться. Особое внимание уделяется фильтрам для обнаружения ошибок.
    *   Назначения (Output): куда обработанные логи будут отправляться (например, в Elasticsearch, на HTTP-эндпоинт для ошибок).
    *   `fluent-bit-current.conf`: Текущая или основная рабочая конфигурация Fluent Bit.
    *   `fluent-bit-modify.conf`: Конфигурация, которая, возможно, модифицирует структуру логов или добавляет/удаляет поля.
    *   `fluent-bit-record-modifier.conf`: Конфигурация для модификации записей логов.
    *   `fluent-bit-final-working.conf`: Возможно, финальная рабочая версия конфигурации.
    *   `fluent-bit-cm-patch.json`: Вероятно, патч для ConfigMap, который применяется к Fluent Bit.

## Общее назначение:

Система Fluent Bit настроена для выполнения следующих задач:
1.  **Сбор логов**: Автоматический сбор логов из всех подов и системных компонентов в Kubernetes.
2.  **Обработка логов**: Обогащение логов контекстной информацией (например, имя пода, неймспейс, метки), фильтрация и структурирование.
3.  **Пересылка логов**: Отправка обработанных логов в централизованную систему хранения (например, Elasticsearch) для последующего анализа.
4.  **Мониторинг ошибок**: Выявление ключевых слов ошибок (Traceback, Exception, ERROR и т.д.) в логах и пересылка их в отдельную систему для оперативного реагирования.
