# Обновленные правила тестирования

## КРИТИЧЕСКИ ВАЖНЫЕ ПРАВИЛА

- **ВСЕГДА** запускать тесты из корня проекта командой: `python -m pytest -v`
- **НИКОГДА** не запускать тесты через `cd tests && pytest` или подобные команды
- **ВСЕГДА** выполнять тесты в контексте корневой директории проекта

## Правила работы с асинхронными тестами

### Использование фикстуры `test_async_db`

Фикстура `test_async_db` возвращает фабрику сессий, которую нужно использовать как асинхронный контекстный менеджер:

```python
@pytest.mark.asyncio
async def test_example(test_async_db):
    # Правильно: используем сессию через async with
    async with test_async_db() as session:
        # Работаем с сессией
        session.add(some_entity)
        await session.commit()
```

### Мокирование SQLAlchemy запросов

Когда вам нужно протестировать код, который делает SQLAlchemy запросы:

1. **Мокирование метода execute для возврата тестовых данных**:

```python
# Создаем тестовые данные
test_data = [Entity(id=1, name="Test"), Entity(id=2, name="Test2")]

# Создаем класс для имитации результата запроса
class MockResult:
    def scalars(self):
        return self
    
    def all(self):
        return test_data
    
    def first(self):
        return test_data[0] if test_data else None

# Заменяем метод execute на мок
async def mock_execute(*args, **kwargs):
    return MockResult()

session.execute = mock_execute
```

2. **Проверка аргументов запроса (если нужно)**:

```python
original_execute = session.execute
calls = []

async def mock_execute(query, *args, **kwargs):
    # Сохраняем вызов для проверки
    calls.append((query, args, kwargs))
    # Возвращаем мок-результат
    return MockResult()

session.execute = mock_execute

# После выполнения тестируемого кода можно проверить вызовы
assert len(calls) == 1
assert str(calls[0][0]).find("Entity") > -1  # проверяем, что запрос был к нужной таблице
```

## Общие правила

- При написании тестов изучай документацию и примеры, чтобы генерировать хорошие проверочные кейсы
- Перед началом работы изучи примеры тестов в папке tests
- Разбирай каждый падающий тест отдельно и очень внимательно. При отладке запускай первый падающий тест и работай до результата.
- Сначала всеми силами старайся решить проблему с тестом, а не с кодом
- Используй примеры других рабочих тестов, чтобы понять как доделать неработающие
- Концентрируйся всегда на одном конкретном тесте, а не пытайся решить все сразу

## Запуск тестов

### Базовые команды
```powershell
# Запуск всех тестов
python -m pytest

# Запуск с подробным выводом
python -m pytest -v

# Запуск конкретного теста
python -m pytest tests/test_models.py::test_function_name

# Запуск тестов по маркерам
python -m pytest -m "slow"
```

### Параметры запуска
```powershell
# Запуск с выводом print-сообщений
python -m pytest -v --capture=no

# Остановка после первого падения
python -m pytest -x

# Подробный traceback
python -m pytest --tb=native
```

## Советы по отладке асинхронных тестов

1. **Проблемы с event loop**:
   - Используйте `@pytest.mark.asyncio` для асинхронных тестов
   - Убедитесь, что фикстура `event_loop` имеет правильную область видимости

2. **Отладка асинхронных запросов**:
   - Добавьте логирование внутри функций-моков
   - Используйте `print()` внутри асинхронных функций для отслеживания выполнения

3. **Ожидание корутин**:
   - Не забывайте использовать `await` для всех асинхронных вызовов
   - Проверяйте, что все асинхронные функции правильно ожидаются
